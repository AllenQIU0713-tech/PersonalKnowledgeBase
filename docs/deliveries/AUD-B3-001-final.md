# AUD-B3-001 最终整改交付

产品决策：用户确认当前没有真实个人资料，只有合成测试数据；对缺陷旧版本生成的问答历史与外发记录执行一次性清空，保留原件、索引和个人记忆，不扩大清理范围。

## 实现

- 新迁移 `AUD-B3-001-clear-legacy-history-v2` 在媒体后台启动前运行，一次性删除 `answers` 与 `outbound`。关联的 `answer_sources` 和 `answer_memories` 随回答级联删除。
- `migration_log` 持久记录执行时间、问答清理数、外发记录清理数和范围说明。重复启动返回同一记录，不重复扩大清理。
- 终端和本机页面显示实际清理数量；`GET /api/migrations` 提供同一审计记录。
- 旧备份没有 `history_schema: 2` 标记，恢复时跳过其中所有问答和外发记录，同时报告跳过数量；原件、分块、个人记忆和删除记录按原规则恢复。
- 新版导出前先应用迁移，再写入 `history_schema: 2`。只有带该标记的备份才恢复新版本生成、来源仍完整且允许外发的问答。
- 新问答仍通过文档级重解析前清理避免再次丢失来源。

## 边界与测试交接

本整改不会删除资料原件、分块、向量或个人记忆。旧备份中的问答历史不会恢复，即使其中部分记录实际未受缺陷影响，这是用户选择的保守清理策略。

固定版本为包含本文的提交，基于 `6cf1cc3`。开发只执行语法编译与静态检查，不执行功能测试。

复测覆盖：完全/部分来源断链旧库首次迁移、清理数量、重复启动幂等、原件/索引/记忆保留、新问答保留、旧备份跳过及数量、新备份安全历史恢复、删除与隐私收紧回归。测试通过后交审计复审 AUD-B3-001。
