## 根因

`Answers.context()` 已同时返回经过后端隐私过滤的 `sources` 和经过 `Memories.eligible()` 资格筛选的 `memories`。`MockProvider.answer()` 只检查和渲染 `sources`，因此仅有合格记忆时错误返回“没有可外发的资料证据”，离线模拟也无法向用户展示记忆是否参与回答。

## 实现

- `MockProvider.answer()` 同时读取当前上下文的资料片段与个人记忆，不重新查询数据库。
- 只在存在资料时输出“资料片段”区，使用 `[资料 N]` 编号。
- 只在存在记忆时输出“个人记忆”区，使用 `[记忆 N｜主题]` 编号并显示正文。
- 两类证据都为空时才显示“没有符合当前使用条件的资料片段或个人记忆”，避免暗示整个知识库不存在记忆。
- 所有分支继续明确“离线模拟，未调用模型”和“不是模型建议”。前端通过 `textContent` 展示回答，资料与记忆正文不会被解释为 HTML 或指令。

## 保持不变的边界

- `Memories.eligible()` 仍是记忆资格入口；`pending`、`conflicted`、`inactive`、`local` 和关联来源隐私收紧的记忆继续被排除。
- `Answers.context()` 的资料隐私过滤、数量与字符预算不变。
- `Answers.generate()` 继续写入实际使用的 `answer_sources`、`answer_memories` 与 `outbound.simulated=1` 记录。
- 离线适配器没有网络依赖，不调用 `DeepSeekProvider`，不写入 `cloud_requests`。
- 真实云端 payload、接收地址、确认令牌、外发记录结构、依赖和端点均未改变。

## 开发检查与独立测试范围

开发只执行差异格式、Python 语法和数据流代码审查，没有执行功能测试。测试任务须在固定归档和隔离数据中验证：

- 仅合格记忆、仅资料片段、混合证据和完全无证据四种输出。
- 记忆主题、正文、类型标题及各自编号正确。
- 待确认、冲突、失效、禁止外发及来源隐私收紧的记忆均不显示。
- UI 按钮、问答历史、`answer_memories`、模拟外发标记及记忆修改/删除后的旧回答清理。
- `cloud_requests=0`、没有真实或模拟的外部网络请求。
- 既有整体回归继续通过，随后交审计复审。

开发不修改或提交 `docs/testing/`、`docs/audit/`、`docs/acceptance/` 中的独立证据。
