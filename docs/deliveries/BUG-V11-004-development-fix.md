# BUG-V11-004 中文记忆检索开发交付

日期：2026-09-29

产品契约：`docs/superpowers/specs/2026-09-29-memory-retrieval-contract.md` R2

状态：开发完成，等待独立测试；不代表测试、审计、用户验收或发布通过。

## 问题与根因

真实记忆主题为“蓝鹭项目会议纪要”，问题为“蓝鹭项目下一次评审时间”。旧 `Memories.eligible()` 只检查完整主题是否出现在问题中，或按空白拆分问题后检查正文。连续中文没有空格，问题也不含完整标题，因此合格记忆在进入 `Answers.context()` 前已被漏掉。

BUG-V11-003 的专项数据曾缩短主题，验证了模拟展示却绕过真实召回条件。为避免继续按单个样例打补丁，本次先由产品任务固定 R2 契约，并处理两处契约矛盾：保留旧 2–3 字精确主题能力；将完整后缀“活动记录”纳入封闭清单，使独立自然问法可以按同一规则解释。

## 实现

`pkb/memories.py` 现在按以下顺序处理：

1. 先排除非 confirmed、local、冲突、来源已删除/无法读取/隐私收紧的记忆。
2. 为中文比较建立 NFKC、casefold、忽略空白和标点的副本，原始数据与展示不变。
3. 使用封闭标题后缀生成一次主题核心；支持非通用 2–3 字完整主题的原问题完全相等查询，不把它扩大为子串召回。
4. 在删除标点前提取 ASCII 字母数字业务编号，允许内部 `-`/`_`，并用完整 token 边界比较；问题中的错误编号会阻断主题旁路。
5. 对完整主题、主题核心和编号的剩余意图统一检查去重 4 字窗口、至少一半覆盖、最后窗口及“上一次/下一次/本次”一致性。
6. 对全部合格候选评分，以精确分数比较覆盖率，按档位、覆盖率、锚点长度、更新时间和 id 确定排序，最后取 5 条。

返回结构仍为 `id/topic/text/sources`。未修改 `Answers`、离线模拟渲染、云端 payload、逐次确认、外发记录或关联清理。

## 隐私与网络边界

资格过滤先于相关性计算；来源读取异常采取排除该条记忆的保守处理。local、pending、inactive、冲突及来源收紧均不能被高相关性绕过。本实现不增加依赖和网络调用，没有执行真实 DeepSeek 请求，也不改变每次云端请求前必须展示实际外发内容并取得单次确认的规则。

## 开发检查与未验证项

开发任务只执行 Python 编译和 `git diff --check`。按照用户分工，本任务不运行功能测试，也不修改或提交 `docs/testing/`、`docs/audit/`、`docs/acceptance/`。

独立测试仍需对固定提交验证：R2 强制正负例、真实 `Memories.eligible()`、Answers 关联、浏览器全链路、超过 5 条的确定性排序、全部资格负例、`cloud_requests=0`、BUG-V11-003 回归、159 项历史回归，以及测试自行设计的不同主题与近似编号样本。随后由测试任务把同一提交交审计复审。
