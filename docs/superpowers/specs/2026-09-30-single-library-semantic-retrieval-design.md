## 1. 最新决定及优先级

用户最新原文：

> 你可以去除我的记忆模块，后续信息的录入统一走资料收集模块。
> 这样对于提问模块的检索来说，只有唯一的资料收集保存的向量数据了。

本决定取代此前“资料与个人记忆分别建索引、双通道检索”的方向。旧 R2/R3 词面规则开发批准继续撤回；尚未交付的双通道草案作废。现行范围只有一个资料入口、一种可检索资料结构、一套当前模型的本地向量索引。

用户已确认：本地语义服务、模型或应检索索引未就绪时暂停自然语言提问，清楚提示原因；仍允许独立精确查找，不静默降级。DeepSeek 仍只在展示本次实际发送内容及预期结果、用户逐次确认后调用。

## 2. 产品结构

保留“资料收集”“查找与提问”及必要的设置、备份功能。去掉“我的记忆”导航、独立编辑、候选确认入口与新建 API；不再维护独立个人记忆检索通道。

文字、图片、PDF、文件以及个人偏好、经历、目标都通过资料收集录入。例如“我不喜欢赶行程”是一条文字资料，可以有标题和标签，不需要用户判断它属于资料还是记忆。图片和 PDF 沿用本地解析/OCR；音视频维持原件保存、标注、精确找回的现有边界，不借本次扩展自动转录。

个人化建议通过检索相关资料获得上下文。取消独立记忆模块不等于删除既有内容，也不新增自动画像或模型训练。未来云端提取/整理的结果若保存，应作为用户核对后的新资料且保留来源；本轮不增加自动生成资料或隐式持续学习。

新回答只展示“资料片段”，引用真实 document_id、chunk_id 和页码/位置。每次准备云端调用都展示统一资料证据，模型、地址、任务指令、实际发送文本、预期结果均可查看，取消不发送。

## 3. 已有个人记忆的保全与迁移

迁移是正常升级步骤，先生成可恢复的本地备份与迁移清单，不能直接清空旧表或历史。备份须说明位置和现有加密状态，凭证不得进入备份。

每条现有个人记忆映射到一条资料：主题为标题，正文原样保留，记录“由旧个人记忆迁移”的来源类型、旧 ID、原始创建/修改时间、来源文档关联以及原状态。按旧 ID 幂等迁移，重复启动不能新增重复资料；不擅自按文本相似度合并不同记录。

| 原记录情况 | 迁移后的提问资格 |
| --- | --- |
| confirmed、allowed、无冲突且来源均有效允许 | 正常文字资料，索引完成后可用于提问 |
| local 或任何来源隐私收紧 | 资料保留“禁止外发”，可本地浏览/精确查找，不进入提问索引 |
| pending、inactive、冲突或来源缺失/不可核验 | 可查看的待核对或停用资料，不自动进入提问索引；保留原因 |

“待核对/停用”在资料详情中处理，不恢复独立记忆模块。激活必须经过用户明确操作，并重新检查来源与隐私；不得用迁移默认值把原本不合格内容改成 ready/allowed。

旧来源关系迁移为资料之间的派生来源关系，原来源删除或收紧时，下游资料必须同步失效或沿用原有安全清理机制。新检索过滤所有不合格派生资料；无效来源或循环关系不可放行。迁移不能把正文保住却丢掉原隐私依赖。

旧问答保留历史标识与追溯关系；通过映射维护迁移后编辑、删除或隐私收紧时的历史清理能力。旧 answer_memories 可作为只读兼容记录，不再用于新检索/新生成。不得为了统一表结构删除用户历史。新回答只写资料引用关系。

迁移分阶段、可重试，记录计数与校验结果；失败期间自然语言提问暂停，用户原数据保持可恢复。验证源内容、状态、隐私、来源关联和条数后才启用新入口。旧存储可只读保留作为恢复依据，不再被日常页面与检索读取；本次不授权永久删除。

恢复旧版本备份时同样执行幂等迁移、删除记录与更严格隐私规则，不能重新出现“我的记忆”模块或双重检索。旧确认全部失效，不跨迁移复用。

## 4. 单一索引与资格

最小单位为资料的真实文本片段；嵌入输入为标题、标签、正文，使用固定字段模板。迁移资料采用完全相同的索引流程，禁止在后台维持第二套个人记忆索引或词面 eligibility 分支。

使用现有已核准本地 Qwen 嵌入模型及本机运行服务；模型文件摘要、查询指令、池化、维度、分块和模板版本固定在交付记录中。比较文本只在本地送给模型。

提问资格为：资料存在且正文解析完成、当前版本有效、allowed、处于可提问状态、所有派生来源仍有效且允许。资格过滤必须先于候选截断，组装上下文与发送前再次验证。禁止外发资料不进入提问向量视图、离线可外发证据或云端预览，仍可在资料浏览/精确查找中本地查看。

向量记录绑定 document_id、chunk_id、源版本/哈希、来源资格版本、模型及模板标识、维度、索引代次。查询与资料采用兼容的同一向量空间；不能仅凭向量存在或数量相等判定有效。

模型上下文容量决定分块，嵌入输入不得静默截断重要正文。标题与标签用于辅助理解，不能重复填充压过正文。原件不解析时明确显示未参与正文检索，不把模型生成的猜测当成提取原文。

## 5. 就绪状态及精确查找

| 状态 | 自然语言提问行为 |
| --- | --- |
| ready | 可语义检索、离线展示、准备云端确认 |
| service_unavailable：未启动、未配置、超时或模型响应无效 | 暂停，说明“语义检索尚未就绪”及原因 |
| indexing/rebuilding：合格已解析资料有待建索引，或升级/恢复需重建 | 暂停，显示完成/待处理数量与进度 |
| index_error：失败、维度/版本异常 | 暂停，提供本地重试或修复入口 |
| no_evidence：服务正常但无可提问资料 | 明确无可用于提问的资料，不伪造回答 |
| no_match：完整检索完成但无足够相关结果 | 明确本次未找到足够相关内容，不混淆为服务故障 |

欠缺索引的计算只包括当前合格且已解析资料。禁止外发、待核对/停用或不支持解析的内容不阻塞其他资料索引，但页面另列未参与正文检索的数量及原因。合格资料索引未完成时，不提供静默的部分语义结果。

独立“精确查找”始终可用：按标题原文、完整业务编号、明确关键词及日期/标签条件找回资料；标明“不理解自然语言问法”。可查看用户本地禁止外发资料，但不能从该入口绕过问答资格。语义未就绪时精确查找不能直接生成自然语言回答或云端确认。

模型服务在请求中途失败，停止该次提问，不回退关键词，不生成确认。准备与发送前复核就绪、证据和索引版本；状态或内容变化使待发送确认失效。已经发送的外部请求无法因关页面撤回，保留现有提示。

外网断开不影响已就绪的本地语义检索。首次下载是明确的维护操作；查询不得自动联网下载模型或切换云端嵌入。

## 6. 更新、删除与一致性

- 新增或解析成功：按当前版本建索引，完成前不宣称可语义检索。
- 修改标题、标签、正文、来源、可提问状态或解析方式：旧向量立即失效，新版本重新索引，旧确认失效。
- 删除或隐私收紧：同步停用对应向量和依赖它的派生资料；后台物理清理失败可见且可重试，不得重新参与查询。沿用已有历史回答与外发记录清理，不扩大删除范围。
- 后台计算期间来源变化：写入前复核版本和资格，旧向量不能覆盖新版本。长时间嵌入计算不占用阻塞全部编辑的数据库锁。
- 查询使用一致版本快照，证据组装前重验；发生变化则本地重试或提示重新查找，不返回失效内容。
- 模型/模板/查询指令/池化/维度变更：重建，不混用向量。备份恢复同样核验版本并尊重删除记录和当前更严格隐私。

## 7. 语义召回与精确增强

1. 验证问题、就绪状态和用户筛选条件，从合格资料片段生成候选集合。
2. 本地生成一次查询向量，遵守该模型查询指令；资料向量不误用查询模板。
3. 对归一化向量计算余弦相似度，从合格集合取至多 40 个候选，先应用实测校准的余弦门槛。零/非有限/维度不一致向量视为错误。
4. 已过门槛候选才参与精确增强。不要求问题与正文含有相同字词，不使用旧标题后缀、四字窗口或固定疑问词表作为语义资格门槛。
5. 精确特征依次为完整业务编号、完整标题、完整标签、完整日期；按此字典序建立精确排名，同特征用稳定源标识打破平分，无精确特征不入该列表。
6. 融合公式为 `score = 0.8/(60+semantic_rank) + 0.2/(60+exact_rank)`，排名从1开始，无精确命中第二项为0。该权重是语义优先的初始排序政策，不是实测最优值；相关性门槛仍基于原始余弦，不能拿融合分数当答案置信度。
7. 最终按融合分数降序、原始余弦降序、稳定源标识升序排列。不用更新时间挤掉相关证据，不为凑数量填入低于门槛资料。

编号使用 NFKC/casefold 和完整边界，BL-2026 不等于 XBL-2026、BL-20260、BL-2026-A。日期为完整日期，不把单独年份或数字作为强命中。不新增隐式实体识别；标题和标签可辅助专名精确匹配，但无匹配不排除语义候选。

最多选6个资料片段，同一文档最多2个，按相关性保留。沿用正文总6000字、单片段最多1200字的预算；在实际发送前展示截断后的准确文本及来源，允许回到原文，不以本地完整显示冒充完整上传。

同一片段不重复。若迁移资料与原资料正文完全重复，可在结果展示时合并相同文本并保留全部来源关联，不能删除原记录、丢掉隐私依赖或当成独立佐证；没有实现可靠的多来源合并时保留可追溯条目，不以文本相似度擅自合并。

## 8. 云端确认与离线展示

新上下文只包含统一资料片段，不再有独立 memories 区。允许随本次重构调整内部 payload 模板和版本，但须保留并重新验证逐次确认：实际内容、指令、模型、地址、预期结果可见；一次性确认绑定本次载荷与当前资料/索引版本；取消不发送、失败不自动重试、变化需重新确认。

旧 pending 确认在升级时全部失效。禁止以“只改变来源类型”为由复用旧令牌。新生成只写资料引用；历史兼容映射维持隐私清理。

离线模拟仅展示选中的资料证据，明确“未调用生成模型，不是模型建议”。后台索引和本地语义检索不需要每次云端确认，因为只访问本机；它们也不授权任何外部请求。

## 9. 真实模型校准

不预设0.5或0.7为通用阈值。开发实现版本化阈值配置与校准入口，未校准前自然语言功能标记为待校准，不默认返回全库近邻。

由独立测试执行真实本机模型测量：固定模型摘要、运行时、维度、池化、查询指令、文本模板、分块与融合公式；使用隔离、人工构造的资料，不采集用户其他私人资料作语料。

- 校准集至少24个查询：至少12个有答案问题、6个近似实体/编号或同实体不同属性难负例、6个无相关内容问题。覆盖人物、日期、地点、负责人、金额以及文字/OCR/标题标签等来源表现。原始缺陷夹具另行原样保留。
- 列出目标与非目标余弦分布，从实测分数间隔选阈值；存在多个满足校准要求的阈值时，选择保留全部指定正例的最高阈值，并记录测量边界和限制。
- 另设至少24个未用于选阈值的独立验证查询，结构同上。强制原始问题全部在最终预算内召回正确来源；通用有答案问题来源召回率至少90%；无答案样本不应产生过门槛证据；明确不同人物/编号/属性的专项负例不得误列为可答证据。报告全部漏召回与误召回，不能把小样本结果宣称为实际准确率保证。
- 若一个阈值无法兼顾正负例，提交失败样本和分数，反馈模型/排序能力不足；不得对已知问题写特判、改验证标签或悄悄调低要求。调整模板、模型、阈值或融合参数需版本化，并重新冻结验证集流程，不在同一验证集上无限调参。

阈值测量不是等待用户猜数字。开发提供可运行入口，测试按既有分工执行，常规配置由开发据证据固化；改变产品范围或引入新服务才反馈产品。

## 10. 强制验收

| 场景 | 数据与预期 |
| --- | --- |
| 原始资料主路径 | 只有资料“蓝鹭项目会议纪要”，正文“蓝鹭项目的内部代号是 BL-2026。下一次评审时间为 2026 年 10 月 8 日上午 10 点。”；查询“蓝鹭项目下一次评审时间”及“蓝鹭项目什么时候再评审”。不能添加重复个人记忆，结果引用真实资料片段 |
| 生日资料新录入 | 通过资料收集保存标题“老爸生日”、正文“老爸生日是1954年2月18日”；原样查询“老爸生日”“老爸生日是什么”“老爸生日是什么时候？”“老爸的生日是什么时候”，均返回该资料 |
| 旧记忆迁移 | 隔离旧库中上述生日记忆迁移为资料，原内容/来源/隐私/时间可核对，幂等重启无重复；新生成只建立资料引用，运行时不调用旧记忆匹配 |
| 不合格旧记录 | pending/inactive/local/冲突/来源缺失或收紧逐项迁移验证，保持待核对/停用或禁止外发，不能变成可问证据 |
| 无答案与难负例 | 近似亲属/项目/编号、相同实体不同属性、无关资料等不因余弦最近就冒充答案；按校准标准验收 |
| 服务中断与索引变化 | 自然语言暂停并说明原因，独立精确入口能找回标题或编号；恢复后完整索引才就绪 |
| 单一入口 | 导航和正常API流程没有独立记忆创建/编辑/确认入口；新资料与迁移资料共用同一索引，旧记忆表只读兼容且不参与检索 |
| 隐私/删除/恢复 | 新旧映射的来源收紧、删除、修改和备份恢复均维持资格与历史清理；旧确认失效 |

从实际存储到检索、上下文、离线展示与外部浏览器全链路验证。禁止用预构造 context、缩短标题、硬编码向量或补建旧记忆让验收通过。独立测试至少覆盖原始蓝鹭和生日UI、迁移、服务中断/恢复、无匹配、确认取消。

质量测试必须用固定真实本地模型；资格、并发、网络失败等确定性测试可用本机假嵌入服务，但不能替代质量验收。

网络边界为：只允许本地UI和固定本机嵌入服务的回环请求；外网、云端嵌入、自动模型下载为零；cloud_requests不增加，模拟标记为simulated=1。精确查找不依赖模型请求。

## 11. 历史测试的显式迁移

| 历史要求 | 新版本处理 |
| --- | --- |
| 原159项中的本地安全、文件处理、引用、隐私、备份、外发确认 | 保留用户保证；接口变化用等价新路径验证 |

| BUG-V11-003/004/005的真实问题和内容 | 原样转换为资料夹具，并独立测旧记录迁移；不再断言词面算法内部过程 |

## 12. 开发与交付顺序

1. 开发基于本文编写计划，首先设计无损幂等迁移与恢复，再移除独立模块，统一资料资格和索引。
2. 实现语义主路径、就绪状态、精确入口、排序及阈值配置、云端确认新版本。按既有职责完成静态检查，不代替独立测试。
3. 独立测试核对历史映射、运行迁移和真实模型校准，冻结参数后用独立验证集与浏览器验收。
4. 开发固化模型/阈值/模板/索引配置并固定候选提交；测试复核同一配置和提交，不能把校准后的新配置当成旧版本已测结果。
5. 审计复查迁移无损性、资格与索引失效、旧历史清理、网络边界和逐次确认。通过后才恢复用户验收。

交付提供统一可重复的模型启动、应用启动、索引进度、精确查找、恢复步骤，不再启动一个没有模型的服务让用户验收自然语言问题。本轮不自动发送真实DeepSeek请求。

## 13. 产品结论

单一资料库设计方案已确认，可以进入开发实施阶段。此前双通道和R3词面补丁均不实施。既有个人内容保全、语义不可用时暂停、精确查找独立、云端逐次确认是不可削弱的交付条件。
