# S2R3 测试冻结包与启动前校验契约

日期：2026-10-17。状态：产品批准测试/审计流程改进，交测试任务实施；不降低 S2R2/S2R3 质量、隐私、资源或来源门槛，不授权正式资料读取、DeepSeek 请求或 Q6_K 下载。

## 问题与目标

S2R2 预运行审计反复发现计划题数、labels、manifest 与冻结状态不一致。QA v3 的计划写20题，labels 实为22项；两套 manifest 仍写“未冻结”。每次人工改一个文件后还需追查其他文件和哈希，候选无法稳定进入独立测试。另一个独立缺口是固定候选尚未接入本地证据复核，不能用召回成功暗示问答成功。

本契约使**一个测试批次只有一个机器可校验的事实来源和一个不可变运行身份**。测试准备与审计冻结只做一次完整交接；任何实质修改都生成新版本，不在旧包上反复修补。它适用于当前 S2R2 QA/browse 和后续 S2R3 reviewer 接线测试。

## 1. 唯一用例登记表

每套测试在独立版本目录保存一个 `case-registry.json`。每个 case 固定唯一 ID、类别（事实/冲突/操作门禁等）、使用的 dataset 记录 ID、问题或操作、预期来源类型与目标片段、预期接受/拒绝/冲突、必要引用要素、禁止出现的来源、适用阶段和是否硬门槛。来源内部枚举为 `collected` / `legacy_memory`，面向用户的标签另由固定映射显示。语义改写案例还登记查询与目标的关键字清单及独立可答理由。

登记表是 case 数量、类别计数、标签和执行列表的唯一来源。`labels.json`、计划中的题数/类别表、manifest 的 case count 与 ID 列表由同一生成器产生，或由同一静态校验器逐字/逐项对照；**不能分别手工维护**。`dataset.json` 可以独立编写，但登记表引用的每个记录/片段必须在 dataset 中存在，未被任何 case 引用的数据及其测试作用也要明确列出。修改登记表或 dataset 后重新生成衍生文件和摘要，保留旧目录，不覆盖已审计版本。

## 2. 不可变运行包

每次候选运行使用新目录，例如 `S2R2-qa-run-v4/`，包含 registry、dataset、生成的 labels/计划摘要、固定测试 profile、候选完整 Git commit、产品规格文件 SHA-256、测试脚本与生成器摘要、模型/运行时标识、执行边界和 manifest。`bundle_id` 为这些实际字节的规范化摘要，不包含会自引用的字段；manifest 记录每个文件 SHA-256 和相对路径。候选来自该 commit 的隔离归档，运行时不得从共享工作树临时读取可变脚本或标签。

测试任务一次性提交 `prepared` 包；审计核对后单独生成冻结记录，列 bundle_id、审核结论、审计任务/提交、带时区时间和覆盖的候选/规格/测试 profile。冻结记录作为内部审计见证，不宣称外部不可抵赖的密码学时间戳。通过后状态为 `frozen`，测试只读运行。`frozen` 包中任何一个受保护字节变化，静态检查自动判旧冻结无效；修订必须复制为新版本目录、重新计算 bundle_id 并重新审计。旧包和审计意见继续保留，不能通过改回旧哈希掩盖变更。

## 3. 候选启动前 preflight

测试入口先运行**不启动模型、不读取正式库、不连云端**的静态 preflight；它返回明确通过/失败和机器可读报告。至少检查：

1. JSON schema、唯一 case ID、登记表/labels/计划/manifest 的数量、类别和执行列表完全一致；所有目标、来源依赖和操作门禁能在 dataset 中解析，来源枚举合法。
2. dataset、registry、labels、测试 profile、规格和测试脚本的当前字节摘要与 manifest/bundle_id 一致；候选完整 commit 可解析，隔离归档摘要匹配，冻结记录准确指向该 bundle_id。
3. 测试 profile 的 `threshold=-1.0` 仅在全新合成临时库使用，报告摘要与 profile 字节绑定；不访问正式资料/正式阈值、不调用真实 DeepSeek。对 Q6_K 等新增模型，来源批准及本机实际文件摘要另按原模型门禁验证，不能因 bundle 冻结替代。
4. 每个测试层的能力声明与候选代码相符：没有已接入且固定的 reviewer 时，问答可回答性层必须标为 `blocked_by_missing_reviewer`，绝不能配置为可通过；本地浏览、两来源召回和隐私层可以独立执行。

任一检查失败，入口必须在候选 API/embedding/reviewer/browser 调用前非零退出；报告写明具体文件、字段和预期/实际值，运行状态记为 `preflight_failed`。不启动候选、不能把未执行项目记为测试失败或通过。测试修包后走新版本，不在失败包上调标签或据模型输出改 oracle。

## 4. 分层报告与责任链

执行报告从冻结包自动读取候选、规格、profile、题数和哈希，不手填。分别给出：

- 本地语义浏览与精确查找独立状态、受限资料仅本机可见及失效；
- 两来源资格过滤、实际向量/余弦分数与排名、零关键词改写、隐私和来源追溯；
- 本地证据复核的原始判断、逐字引用、难负例与无答案拒绝；
- 最终回答/云端确认载荷的来源与版本、失败关闭；
- 未执行、阻断及资源/浏览器/真实提供方仍待验证的范围。

每层只有其自身证据才可标 `passed`。没有 reviewer 或 reviewer 未经质量验收时，完整 QA 必须 `blocked` 或依据真实误放记 `failed`；浏览/召回通过不升级为 QA 通过。真实 DeepSeek 调用仍按逐次实际载荷确认，不在这些合成测试中执行。`calibration_required` 继续保持。

责任顺序：**测试生成 prepared 包 → 审计静态复核并冻结 → 测试入口自动 preflight → 独立运行 → 审计复核原始结果**。开发只提供固定候选与可测说明，不修改测试 oracle。若预审发现问题，测试在新版本目录一次修正并重新交审计；审计只对新 bundle_id 放行。总负责只依据冻结包和报告更新进度，产品负责能力与验收口径，不代跑代码测试。

## 5. 当前批次处理

QA v3 与 browse v2 当前哈希虽与 manifest 匹配，但未冻结，且 QA 计划20/22不一致。两套维持 `preflight_failed / not_run`，原目录作为发现记录保留。测试任务先实现或使用一个轻量生成/校验入口，创建新版本包：QA 登记表含20个事实/冲突用例及2个操作门禁，browse 登记表含14项，实际数量以登记表生成的结果为准。审计核对零关键词改写与标签唯一性后冻结；测试入口验证成功才执行固定候选 `4e8e8cac10452b5e0b565902bd191acba90dd26f` 的可独立测量层。S2R3 reviewer 接线候选另建新包，不复用这个批次的“完整 QA 通过”结论。

此改进由测试任务实现静态工具与冻结包，审计复核，开发提供固定候选。它不需要用户批准新模型、下载或云端调用；Q6_K 仍为 `approval_blocked`，完整来源审批材料齐备前不得向用户请求新增下载批准。
