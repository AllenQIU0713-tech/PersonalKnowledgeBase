# V1.1 中文个人记忆检索契约

日期：2026-09-29。状态：产品批准，供 BUG-V11-004 开发、独立测试与审计执行。

本文件取代本轮聊天中对方案 A 的初步批准。业务代码由「实施产品设计方案」任务修改，本任务只负责产品规则与交接。本次批准为现有记忆检索的纠错，不授权真实云端请求或扩大资料外发范围。

## 1. 问题与交付目标

BUG-V11-003 修复了模拟回答不展示已检索记忆的问题，未修复中文记忆召回。之前专项测试缩短了真实主题，绕过了生产问题。BUG-V11-004 必须验证完整链路：原始记忆存储 → 资格过滤 → 相关性检索与排序 → Answers.context() → 模拟展示及关联记录 → 浏览器可见结果。

目标是确定性、可解释、不依赖分词包或模型服务的本地词面检索。它支持明确主题、业务编号与正文措辞相近的问题；不承诺同义改写、无实体问题或跨记忆推理的通用语义理解。现有本地向量能力不与隐私过滤矛盾；本轮不引入记忆向量索引，是为控制修复范围与运行依赖，不能解释为向量检索天然不适合隐私控制。

## 2. 不可改写的原始回归基线

- 主题：`蓝鹭项目会议纪要`
- 正文：`蓝鹭项目的内部代号是 BL-2026。下一次评审时间为 2026 年 10 月 8 日上午 10 点。`
- 问题：`蓝鹭项目下一次评审时间`
- 属性：confirmed、allowed、无冲突；有来源时来源仍为 allowed。

专项测试与外部浏览器必须原样创建、保存、读取和查询以上内容，不允许缩短主题、修改正文、插入辅助词或事先构造一个已经命中的 context。可增加变体，但不能替换原始基线。

## 3. 匹配前资格与数据边界

相关性评分前排除 pending、inactive、local、冲突记忆，以及来源已删除、无法解析或隐私已收紧的记忆。来源异常采取不参与的处理，不把整次检索变成放行或泄漏内部异常。不得改变已有冲突判定与隐私规则。

评分不更新原始主题、正文、更新时间、隐私或记忆状态。对所有合格候选评分后再截取前 5 条，不能依赖数据库先返回哪 5 条。下游数据形状、关联记录、云端 payload 与逐次确认保持原有契约；相关证据变化继续受确认失效检查约束。

## 4. 两种文本表示

### 4.1 中文词面比较

对比较副本做 Unicode NFKC 和 casefold。忽略空白和标点用于中文主题/意图比较，保留字母与数字，使用相同处理比较查询、主题与正文。原文保存和展示不变。

### 4.2 业务编号比较

编号必须在删除标点之前单独提取，不能使用上面的去标点字符串做编号子串匹配。编号定义为包含至少一个 ASCII 拉丁字母和一个数字的完整 token，可包含内部 ASCII `-` 或 `_`；边界是该 token 字符集以外的字符，因此中文紧邻编号也能识别。NFKC/casefold 统一全角与大小写，不额外把其他连接符替换成 ASCII 连字符。

`BL-2026` 不等于 `XBL-2026`、`BL-20260`、`BL-2026-A` 或 `BL2026`。纯年份、日期、时间、数字与连接符不作为强编号。若查询含此类明确编号，候选至少含一个完全相同编号；不允许通过主题分支绕过不匹配编号。纯自然语言日期不是业务编号。

## 5. 主题与意图

### 5.1 主题锚点

按最长后缀优先，仅从标题末尾剥离一次：会议纪要、会议记录、备忘录、工作日志、笔记、记录、纪要、总结、方案、计划、资料、清单。不重复裁剪，防止把实体本身裁没。只使用长度至少 4 的剥离后核心；本例为“蓝鹭项目”。完整原主题继续保留为候选锚点。

完整主题锚点也要求至少 4 字符，且不能仅是上述通用后缀；不能靠“完整主题”分支绕过短词限制。该 4 字下限是本轮抑制泛匹配的保守边界，并不意味着所有 4 字词都是实体。长度为 2–3 的单独短词不自动扩大匹配；合法完整编号按编号规则处理。

### 5.2 有界问句清理

允许从问题开头去掉一次“请问”或“请告诉我”，从末尾去掉一次“是什么”或“吗”；主题/编号锚点后紧接的一个“的”可去掉。只在上述位置处理，不全局删除字词；不对“时间”“地点”等实义内容作同义替换。清理顺序与最长前缀优先必须固定。

取查询中出现的最长主题锚点，完整主题优先于核心；去掉其单次出现后得到剩余意图。只有编号匹配时，按同样方式去掉匹配编号得到意图。主题和相同编号同时出现时可去掉这两个已经验证的锚点；多个实体比较不作为本轮强制覆盖场景。

### 5.3 意图验证：有意图时，所有锚点分支都要验证

意图为空：允许纯完整主题、纯核心或纯编号检索。

意图非空：至少 4 字符；生成去重后的连续 4 字窗口。要求同时满足：

1. 至少一半窗口在正文比较副本中连续出现（命中数 ≥ ceil(窗口总数 / 2)）；
2. 意图最后 4 字窗口也必须在正文中连续出现；
3. 若意图含“上一次”“下一次”“本次”，正文必须出现与该限定语相同的表达；不因其他窗口重叠而混淆不同批次。

所有锚点分支，包括完整标题和强编号，都不能绕过意图验证。不要把一条同项目但内容不同的记忆当成问题答案。

理由：4 字窗口相较 2 字更不易被“项目”“会议”“时间”之类片段触发；一半覆盖容忍部分差异，但不代表概率或正确率；末尾窗口约束用于防止共享前缀掩盖不同询问目标，如“下一次评审地点”与“下一次评审时间”；批次限定约束防止“上一次”误中“下一次”。这些是可审计的保守规则，不是经过语料校准的最优阈值，也不保证任意中文句式都能召回。

若正文同时涉及多个事件，上述规则只表示候选相关，不能断言时间、地点与实体的关系已被理解。离线模拟只展示原文证据。不得为追求命中而在无匹配时自动放宽到无实体的正文短词匹配。

## 6. 排序与结果

匹配依据分档：完整主题或完整编号为 3 档，主题核心加通过验证的意图为 2 档，纯主题核心为 1 档。同一候选满足多个分支只出现一次，保留最佳合法分数。

固定排序：档位降序 → 意图窗口覆盖率降序 → 锚点匹配长度降序 → updated 降序 → id 升序。无意图覆盖率记为 0；覆盖率使用分数比较避免浮点细微差异。updated 仅作相关性相同后的次级排序，不作为是否相关的依据。最多返回 5 条。

同一数据快照与查询必须产生相同顺序。内部匹配理由可供本地测试断言，不向云端额外发送、不在普通日志写入记忆正文；不要为展示理由更改已有上下文或 payload 结构。

无匹配含义是“本次本地匹配未找到符合条件的个人记忆”，不等于库中不存在相关内容。若需要说明限制，提示尝试完整主题或业务编号，不声称已做语义检索。具体页面文案如需变更，随本轮交付列明。

## 7. 强制正负例矩阵

以下默认使用第 2 节原始记忆；除指明外，不改其主题与正文。

| 查询或场景 | 预期 |
| --- | --- |
| 蓝鹭项目下一次评审时间 | 命中原始记忆 |

| 蓝鹭项目会议纪要 | 完整主题命中 |
| 蓝鹭项目 | 核心命中 |

| BL-2026 的下一次评审时间 | 编号加意图命中 |
| 蓝鹭项目预算金额 | 不命中 |
| 蓝鹭项目下一次评审地点 | 不命中，专门捕获一半窗口的误命中 |
| 蓝鹭项目上一次评审时间 | 不命中 |
| 蓝鹭项目会议纪要预算金额 | 不命中，完整标题不能绕过意图 |
| BL-2026预算金额 | 不命中，编号不能绕过意图 |
| 红鹭项目下一次评审时间 | 不命中原始记忆 |
| 蓝鹭项目XBL-2026 | 不命中，错误编号不能被核心绕过 |
| 项目、会议、时间、评审、评审会、会议纪要、下一次评审时间、2026 | 单独查询均不命中原始记忆 |
| XBL-2026、BL-20260、BL-2026-A、BL2026 | 不命中原始记忆 |
| 查询 BL-2026，库中仅有上述近似编号记忆且无精确编号 | 不命中；两方向都要测 |
| 同为蓝鹭项目、但主题是蓝鹭项目预算记录、正文仅谈预算 | 评审时间问题不能命中这条记忆 |
| 另一项目记忆正文包含完全相同评审时间短语 | 蓝鹭项目问题不能命中另一项目 |
| 主题为海棠读书会活动记录、正文为下一次活动地点为二楼阅览室；查询海棠读书会下一次活动地点 | 命中，验证规则没有硬编码蓝鹭或评审 |
| 合格且可匹配的记忆超过 5 条 | 按第 6 节排序，恰取前 5 条，无重复；打乱数据库枚举顺序仍一致 |
| 原始记忆分别为 pending、inactive、local、有冲突、来源 local 或已删除 | 每种单独不参与，无论完整标题、编号还是核心是否命中 |

每个用例使用隔离数据，避免新建同主题差异记忆产生冲突而混淆相关性测试。测排序时，候选档位与更新时间故意相反；测隐私时保留一个匹配的 allowed 对照，避免全部返回空也被误判为通过。

不强制承诺“蓝鹭下次几点开会”这类实体缩写与同义改写召回；若用户需要这种能力，应另行设计本地语义记忆检索，不能通过暗改本轮阈值伪装覆盖。

## 8. 测试、审计和关闭条件

1. 测试任务通过真实存储接口建立数据，直接调用实际 Memories.eligible() 验证完整矩阵；禁止只对辅助评分函数或预构造 context 测试。
2. 验证实际 Answers.context()/generate()，确认记忆进入回答、answer_memories 保留关联、simulated=1、cloud_requests=0。同时覆盖修改/删除/隐私收紧后的关联回答清理和旧云端确认失效。
3. 外部浏览器原样复现第 2 节，见到原主题与正确正文；再验证自然提问变体、评审地点负例及隐私排除。保存结果与截图，不用模拟上下文替代浏览器全链路。
4. 记忆匹配不新增任何网络调用。离线模拟不访问 DeepSeek；原有本机 HTTP 界面不属于云端外发。不得为了本轮验证安装云端依赖或发送真实请求。
5. 原 159 项有效历史回归、BUG-V11-003 的既有有效专项及本轮新增矩阵都必须通过，不能用新增测试总数掩盖旧失败。需替换的旧断言必须逐项说明与本契约的冲突，并经测试/审计认可，不能静默删除。
6. 测试独立增加至少一组未由开发使用的不同主题/正文词面样本及近似编号反例，检查过拟合。若发现契约自相矛盾或基本误匹配，反馈产品更新版本，不直接调阈值至测试通过。
7. 审计对固定提交复核隐私过滤顺序、编号边界、确认失效及无新增外发。开发完成、测试通过、审计通过、用户验收分别记录。不得提前关闭问题或宣称正式可用。

## 9. 实施边界

开发依据本契约编写实施计划和代码，按既有分工完成静态检查并交独立测试。只改本地记忆匹配、必要的匹配结果说明及交接文档；不顺便重构来源检索、增加云端请求、修改清理策略或引入通用语义服务。本契约覆盖整个已知故障链，但不保证未来不存在新缺陷。
