# BUG-V11-004 中文记忆匹配设计

## 目标

为 `Memories.eligible()` 增加稳定、可解释、完全本地的连续中文匹配，使真实主题“蓝鹭项目会议纪要”能够响应问题“蓝鹭项目下一次评审时间”，同时拒绝不同项目、无关意图、通用短词和不完整业务代号。

本设计是保守的字符级相关性规则，不宣称通用中文分词或语义理解。记忆资格与隐私过滤继续先于相关性评分；所有合格候选评分后排序，最后截取 5 条。

## 永久真实回归基线

专项与外部浏览器测试必须原样使用以下数据，不得缩短主题、改写正文或预先构造 `context` 绕过 `Memories.eligible()`：

- 主题：`蓝鹭项目会议纪要`
- 正文：`蓝鹭项目的内部代号是 BL-2026。下一次评审时间为 2026 年 10 月 8 日上午 10 点。`
- 状态：`confirmed`
- 隐私：`allowed`
- 冲突：无
- 问题：`蓝鹭项目下一次评审时间`

浏览器测试必须从 UI 新建该记忆，再通过“离线模拟回答”验证正文中的评审时间。

## 处理顺序

### 1. 资格过滤

继续使用现有条件，且在计算相关性前完成：

- `status == confirmed`
- `privacy == allowed`
- 不存在冲突
- 每个关联来源当前仍为 `privacy == allowed`

任何不合格记忆都不参与评分。不得通过匹配强度绕过 `pending`、`inactive`、`local`、冲突或来源隐私收紧规则。

### 2. 文本规范化

中文主题、问题和正文使用 Unicode NFKC 与 `casefold()`，然后仅保留 Unicode 字母和数字。该处理统一全角、大小写、空格和标点差异，但不删除任何实义字词。

问题只允许剥离一次明确列出的套话：

- 前缀：`请问`、`请告诉我`、`我想知道`、`想问一下`、`关于`
- 后缀：`是什么`、`是多少`、`在哪里`、`是谁`、`什么时候`、`怎么样`、`怎么办`、`吗`、`呢`

使用最长匹配优先。主题核心与后续意图之间紧邻的一个“的”可作为连接词移除；其他文字不得全局删除。

### 3. 主题核心

从规范化主题末尾只剥离一次最长的说明性后缀：

`会议纪要`、`会议记录`、`项目纪要`、`项目记录`、`工作日志`、`备忘录`、`笔记`、`记录`、`纪要`、`总结`、`方案`、`计划`、`资料`、`清单`。

真实主题因此得到核心“蓝鹭项目”。不能继续把“项目”剥离为“蓝鹭”。模糊匹配要求主题核心至少 4 个规范化字符。

完整主题精确等于问题时允许命中。2–3 字主题只在问题规范化后与主题完全相等、含 Unicode 字母且不属于通用短词时命中，用于保留“旅行”“目标”“备份”等既有精确行为。`项目`、`会议`、`时间`、`记录`、`纪要`、`资料`、`内容`、`事情`、`问题`及纯数字不能通过短主题分支。

### 4. 正文意图覆盖

问题包含完整主题或主题核心但还有额外文字时，移除该主题锚点和一个紧邻的“的”，把剩余部分视为问题意图。

- 意图少于 4 个规范化字符时不做模糊命中。
- 对意图生成全部连续 4 字窗口。
- 统计这些窗口中有多少原样出现在规范化正文。
- 至少命中 1 个窗口，且命中比例不低于 50%，才认为主题与正文意图共同成立。

真实问题的主题锚点是“蓝鹭项目”，剩余意图是“下一次评审时间”；其连续 4 字窗口全部出现在正文，因此命中。`蓝鹭项目预算金额` 的意图窗口不在正文，因此不命中。`红鹭项目下一次评审时间` 没有“蓝鹭项目”主题锚点，即使正文含通用评审短语也不命中。

### 5. 业务代号

业务代号在保留规范化连接符的文本上单独解析：

- 先将常见 Unicode 横线统一为 ASCII `-`，并做 NFKC 与 `casefold()`。
- 候选只包含 ASCII 字母、数字及内部连接符。
- 候选长度至少 4，且必须同时含拉丁字母与数字。
- 问题与记忆主题/正文的代号集合必须存在完全相同的 token 才命中。

因此 `BL-2026` 可强命中；纯 `2026`、年份、日期和时间不能。`BL-2026` 不得匹配 `XBL-2026`、`BL-20260` 或 `BL-2026-A`。

## 评分、排序与上限

每个合格记忆只保留最高匹配路径，优先级为：

1. 完整业务代号一致；
2. 问题与完整主题精确相等；
3. 问题与主题核心精确相等；
4. 完整主题加正文意图覆盖；
5. 主题核心加正文意图覆盖。

同一优先级按正文意图覆盖率、命中的 4 字窗口数、锚点长度降序排列。仍相同时按 `updated` 降序，再按 `id` 升序，得到可重复结果。完成全部合格候选的评分与排序后，返回前 5 条。

本层只选择相关证据，不保证证据包含最终答案。离线模拟继续原样展示资料与记忆，不生成推测；云端模型仍需用户逐次确认，且本次不修改其 payload。

## 文件范围

- `pkb/memories.py`：增加规范化、主题核心、业务代号、正文意图覆盖、相关性评分和确定性排序。
- `docs/development-status.md`：记录验收暂停、根因和整改状态。
- `docs/development-testing-handoff.md`：记录永久真实夹具与独立测试矩阵。
- `docs/deliveries/BUG-V11-004-development-fix.md`：记录算法、安全边界和未验证项。
- 开发不修改或提交 `docs/testing/`、`docs/audit/`、`docs/acceptance/`。

## 测试契约

独立测试必须直接调用真实 `Memories.eligible()`，并通过外部浏览器覆盖真实数据。测试矩阵至少包括：

- 原始问题、带标点/空格/全角变化、`请问蓝鹭项目的下一次评审时间是什么？`
- 完整主题、主题核心、`BL-2026`
- `红鹭项目下一次评审时间`、`蓝鹭项目预算金额`
- 仅 `项目`、`会议`、`时间`、`2026`
- `XBL-2026`、`BL-20260`、`BL-2026-A`
- 同实体不同议题、多记忆相关性排序、更新时间和 id 决胜、超过 5 条时的上限
- `pending`、`inactive`、`local`、冲突、来源隐私收紧
- 离线模拟不建立网络连接，`cloud_requests=0`
- 既有完整回归继续通过

测试和审计完成前不得关闭问题或恢复用户验收。
