# BUG-V11-002 可用片段反馈设计

## 目标

修复“查看并选择可用片段”在长页面中看似无响应的问题。用户点击后应立即在按钮附近看到处理中状态，完成后无需寻找即可看到并聚焦结果；空问题、无匹配和接口失败都必须有明确反馈。

本次只改善本地片段预览交互和检索模式说明。片段选择、禁止外发过滤、确认令牌失效、逐次云端确认和外发记录逻辑保持不变。查看可用片段不得触发云端请求。

## 交互流程

### 开始请求

- 按钮组下方保留一个常驻状态行，使用 `role="status"`、`aria-live="polite"` 和 `aria-atomic="true"`。
- 点击后立即把状态行更新为“正在查找可用片段…”。
- 预览按钮在请求期间禁用，设置 `aria-busy="true"`，按钮文字同步改为“正在查找…”，防止重复触发。
- 发起新请求前沿用现有确认失效流程，使已有一次性确认令牌失效。
- 每次请求持有递增序号。只有仍是最新序号且问题文本未变化的响应可以更新界面；旧请求晚到时直接丢弃，不能覆盖新结果，也不能恢复旧确认状态。

### 空问题

- 不发送接口请求。
- 状态行显示“请输入问题后再查看可用片段。”。
- 焦点回到问题输入框，帮助键盘用户立即修正。
- 按钮恢复可用，`aria-busy` 恢复为 `false`。

### 成功与无匹配

- 结果区先渲染一个可编程聚焦的标题，使用 `tabindex="-1"`。
- 有片段时标题为“可用片段”，保留现有复选框、来源信息、允许记忆和禁止外发资料已排除提示。
- 无片段时标题为“没有检索到可用资料片段”。仍允许后续准备仅包含问题与允许记忆的请求。
- 状态行同步给出完成结果，例如“已找到 1 个可用片段”或“没有检索到可用资料片段”。
- 如果本次实际只使用关键词检索，无匹配说明必须包含：“当前仅使用关键词检索，请尝试资料标题、代号或关键词。”该文案不得暗示资料一定不存在。
- 渲染完成后对结果标题调用 `focus({preventScroll:true})`，再调用 `scrollIntoView()` 使标题进入视口。正常情况下使用平滑滚动；用户启用 `prefers-reduced-motion: reduce` 时使用即时滚动。

### 失败

- 状态行显示简短失败信息，结果区同时渲染标题“无法查看可用片段”和可操作的错误提示。
- 失败标题采用与成功结果相同的聚焦和滚动策略，错误不能只出现在页面顶部的全局通知中。
- 按钮在 `finally` 中恢复文字、禁用状态与 `aria-busy`。

## 实际检索模式

`/api/answers/preview` 的响应增加本次请求实际使用的检索模式，而不是只返回服务配置状态：

- `semantic`：本次语义检索成功参与结果。
- `keyword`：没有配置本地向量服务，本次只使用关键词检索。
- `keyword_fallback`：配置了本地向量服务，但本次语义请求失败并回退关键词。

响应只包含界面需要的稳定模式值和简短、用户可读的原因，不返回本机路径、端口、堆栈或内部异常。前端依据该字段解释当前结果；`keyword_fallback` 不得显示为语义检索正常但没有匹配。

为保证“本次实际模式”准确，向量检索层在一次调用内返回结果与模式元数据，回答上下文直接传递该元数据。文档查找页面继续使用已有状态显示，不改变检索算法和排序。

## 并发与状态边界

- 预览请求的递增序号只管理界面更新，不持久化。
- 问题输入发生变化时立即递增序号、清除当前预览并使确认令牌失效。
- 旧请求即使成功返回，也不能写入 `answerPreview`、结果区、状态行或按钮最终状态。
- 请求期间按钮禁用用于常规防重复；序号检查用于处理程序化触发、输入变化和网络乱序。
- 预览接口继续只读取本地资料、索引和允许记忆；不新增任何外部端点。

## 文件范围

- `pkb/static/index.html`：增加按钮附近的实时状态区域，并补充结果区的可访问性关联。
- `pkb/static/app.js`：实现处理中、防重复、结果聚焦滚动、空问题与错误反馈、请求序号保护，以及实际检索模式文案。
- `pkb/static/style.css`：为状态行、结果标题和减少动态效果提供必要样式，不改变整体视觉系统。
- `pkb/embedding.py`：让单次检索返回结果和实际使用模式。
- `pkb/answers.py`：把实际检索模式加入预览响应，保持隐私过滤顺序不变。
- 开发状态与交接文档：记录根因、固定提交和测试范围；不修改 `docs/testing/`、`docs/audit/` 或 `docs/acceptance/`。

## 验收边界

- 页面超过一屏时，点击后可在当前操作附近看到处理中，完成后结果标题进入视口并获得合理焦点。
- 鼠标、键盘和屏幕阅读器可以理解处理中、成功、无匹配和失败状态。
- `BL-2026` 可返回允许外发的蓝鹭片段；未启用语义模型时，完整无空格中文问题允许无匹配，但必须显示关键词模式提示。
- 赤狐禁止外发资料的标题、识别码和正文不得进入可选片段或确认 payload。
- 问题变化、乱序响应和已有确认令牌不会恢复旧预览或旧确认。
- 取消路径和外发记录保持为 0，不发起真实 DeepSeek 请求。

## 方案取舍

采用“操作附近实时状态 + 结果标题聚焦滚动”。只显示附近状态无法解决长页面中寻找结果的问题；弹窗或 toast 会打断键盘流并割裂现有片段选择流程。当前方案在原有页面结构内提供可见反馈，并把对业务逻辑的影响限制在本地预览状态传递。
